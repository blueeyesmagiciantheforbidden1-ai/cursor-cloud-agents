# Capability target and acceptance

The owner's ambition is a progressively more capable self-improving intelligence hub.
There is no established engineering acceptance test that proves a singularity or
unbounded superintelligence. Those terms are aspirations, not operating modes or
claims made by this application.

Each iteration must identify a concrete weakness, preserve a reproducible failure,
propose a bounded change, and demonstrate improvement under a frozen evaluator.
Successful work can also motivate improvements to planning, code, tools, shared
context, search procedures and collaboration. Improvements must be measured
against a strong simpler baseline and retain the full cost of failed attempts,
verification and rollout. More agents or longer loops alone do not qualify.

The owner allocated 25% of included subscription allowance to improvement and
75% to project work. Urgent foreground work takes priority. Unknown or stale
usage and missing authoritative accounting pause autonomous model improvement.
The current allocation planner is not a production meter or billing guarantee;
automatic model improvement remains disabled until the dispatcher enforces it.
No instruction in a research artifact changes those spending constraints.

The imported Ryan Frontier engine is a finite, offline workflow-repair experiment.
Its separate cloud service admits at most four explicit requests per UTC day,
one at a time, with no provider calls. Child CPU, wall time, memory and output
limits bound individual runs; ordinary Cloud Run, build, storage and database
charges still apply. This small commissioning experiment does not establish
general code repair, five-agent readiness or a scientific improvement in general
intelligence. Inconclusive evidence stays inconclusive.

Production code improvements require a candidate tied to exact source, independent
checks, protected evaluator and permissions, staged verification, health evidence
and a retained rollback target. A failure should create a regression case and
targeted repair proposal. An uncertain external outcome must first be reconciled;
it must not trigger duplicate spending or a blind restart. Trusted budget,
identity, evaluation and release controls remain outside candidate authority.

Current implementation and boundaries are recorded in
`CODEX_PACKAGE_INTEGRATION.md`, `LEARNING_AND_RECOVERY.md` and
`SELF_IMPROVEMENT_REQUIREMENTS_20260921.md`. Neither model weights nor account
allowances are merged by sharing tasks, verified artifacts and lessons.
