# Codex_Package / Ryan Frontier integration review

Review date: 2026-09-21. This document distinguishes source inspection and local tests from a cloud deployment or a scientific improvement claim.

The supplied package is a useful, executable finite research engine. It learns and compares repair search policies in a closed 32-program language, exports generated programs, and records experimental evidence. It does not contain native transports for the five coding agents, train model weights, discover a general learning algorithm, or deploy changes to the hub.

## Concrete integration decisions

1. Preserve the reviewed package without source modifications. Hash-check the bundled Python modules against its import provenance before execution. Preserve the full supplied ZIP separately so its larger historical evidence is not silently discarded.
2. Use one isolated temporary output directory per accepted request. `cli.execute` creates a fresh UUID task/run every call and overwrites convenience `report.json`, `summary.json` and `generated/` locations. The caller must deduplicate before invoking it, and retain immutable `runs/<run_id>` receipts rather than interpreting a shared latest file as authority.
3. Keep cloud authority outside the research child. The dedicated database owns the active slot, request identity and four-run daily charge. The per-run SQLite ledger/registry is archived evidence. Use a separate service account, no provider secrets, private invocation from the hub runtime, scale to zero and one configured instance. Deployment/IAM verification is a separate commissioning step.
4. `ResearchService.run` accepts only request ID, workspace, seed, units and budget. Seed is 0..2147483647; units/budget are 1..8. Admission atomically records request+global slot+day charge. Retryable transaction callbacks perform no runner or archive I/O. Only confirmed commit authorizes one synchronous runner call.
5. Runner output must bind the exact source ZIP, normalized parameters and an immutable `frontier/runs/<request_id>/<sha256>.tar.gz` object generation in the fixed bucket. The trusted runtime verifies actual object/report/receipt bytes and confirmation rules; the admission layer validates bounded JSON and exact publication. Summary output excludes local output paths. Cloud object references are evidence, not public signed URLs.
6. Lost reservation acknowledgment produces no dispatch. Runner/archive/publication uncertainty retains its reservation and never refunds or starts a successor automatically. `get` only reads. A separately reviewed operator reconciliation procedure is required to resolve a stranded run; this module intentionally supplies no public reset or expiry takeover.
7. Publish results as research evidence only. Existing `agent_hub/learning.py` already has proposal/review/retirement and selected lesson handoffs. Existing `research.py`, `contracts.py`, `workflows.py`, `transfer.py` and `routing.py` contain related offline contracts. Reuse these boundaries rather than maintaining a second competing production budget, account catalog or release authority. A future bridge can propose a narrowly scoped lesson with exact run/artifact provenance; it must not silently mark a research artifact as an accepted lesson or deployed patch.

## Verified limits and readiness

The package's learned family reserves its final unsolved slot for mask 31, the existing complete set of human-authored guards. That makes completion within the finite task family expected and provides a useful strong baseline; it does not show a new reasoning primitive or an advantage over proposing that baseline first. With the cloud pilot's deliberately small lineage count, confirmation remains statistically inconclusive by construction. No model or cloud provider spend should be added to make this bounded commissioning test appear more impressive.

This review found no blocker to running the inspected domain/research tests. The main integration hazards are duplicated work after HTTP retries, ephemeral SQLite mistaken for cloud authority, local registry approval mistaken for authenticated deployment approval, mutable convenience outputs mistaken for immutable evidence, and interpreting zero model spend as zero cloud cost. The new service addresses durable admission/publication; the root runtime/deployment work must still demonstrate the real Linux suite, private invocation, artifact persistence and end-to-end manager tool before calling the integration live.
